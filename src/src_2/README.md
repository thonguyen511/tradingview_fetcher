# TradingView Automated OHLCV & Corporate Actions Pipeline (`src/src_2`)

A production-grade, distributed data ingestion and maintenance pipeline built upon the CSV outputs generated by `src/src_1`.

---

## 1. Key Architectural Features

- **Dual Ingestion Sub-Processes**:
  - `initial_run`: Full historical back-paging loop to Day 1 (exchange inception) for all intervals. Uses Premium/Ultimate credentials on `prodata.tradingview.com` for deep intraday data (1, 5, 15, 60, 240m) while macro intervals (1D, 1W, 1M) run concurrently on Free accounts. Falls back gracefully to Free accounts for testing.
  - `weekly_run`: 100% Free accounts. Fetches the latest 300 candlesticks, finalizes unclosed prior-week bars, updates newly formed bars, and pulls corporate actions.
- **Corporate Action Extraction**:
  - **Stock Splits**: Full historical splits back to IPO retrieved via WebSocket Quote Session (`last_splits`).
  - **Dividends**: Gross payout, ex-dividend date, split-adjusted payout, and payment date (`Dividends@tv-basicstudies-277`).
  - **Earnings & Revenue**: Diluted EPS actual, Wall Street consensus estimate, revenue actual, revenue estimate, fiscal period, announcement date, and timing (`Earnings@tv-basicstudies-277`).
  - **Continuous Futures Rollovers**: Full history of contract switch dates and contract codes (`BarSetContinuousRollDates@tv-corestudies-48`).
- **Hugging Face 8TB Storage Limit Protection**:
  - Operates on a single 500MB chunk basis (fits on Kaggle/runner 19GB disk limit).
  - Overwrites overlapping bars using `keep='last'`.
  - Executes `api.super_squash_history()` on Hugging Face to permanently purge old overwritten Git blobs and eliminate hidden Git history bloat.
- **100% Raw Unadjusted Prices**:
  - Enforces `{"symbol": symbol, "adjustment": "none"}` across all queries.
- **Dynamic Intraday Filtering**:
  - Probes 1D timeframe first to extract `has_intraday` from symbol resolution metadata.
  - Automatically skips intraday intervals for symbols that do not support intraday data (bonds, economic series, certain indices).
- **Zero-OOM Memory Safety**:
  - Processes and serializes interval-by-interval to Parquet. Purges RAM after each interval with `gc.collect()`, keeping memory consumption under 1.5 GB.
- **Greedy Workload Balancing (`map.json`)**:
  - Distributes CSV files across 20 concurrent notebook nodes.
  - Slices symbols into fixed chunks of 5,000.
  - Scalable: supports adding new CSV files and appending new rows to existing CSVs without disrupting established chunk mappings.
- **20 Concurrent Kaggle Workers Across 4 Accounts**:
  - Dispatches 5 notebooks per account across 4 Kaggle accounts (`thonguyen511`, `hero0511acc`, `tqunacc`, `acc3conheo`).
  - Supports multi-day execution with persistent `checkpoint.log` and `failures.log` synced to Hugging Face.

## 3. How to Run

### Interactive Menu
```bash
python -m src.src_2.main
```

### Initial Run (Deep Historical Ingestion)
```bash
# Run for Node 0 (Processes workload chunks assigned in map.json)
python -m src.src_2.main --mode initial --node 0
```

### Weekly Run (Maintenance & Candle Finalization)
```bash
# Run for Node 0
python -m src.src_2.main --mode weekly --node 0
```

### Greedy Map Maintenance
```bash
# Incrementally update map.json after new CSVs are added or rows appended
python -m src.src_2.main --mode map
```

### Kaggle Multi-Account Orchestration
```bash
# Dispatch all 20 notebooks across the 4 Kaggle accounts
python -m src.src_2.orchestration.kaggle_dispatcher dispatch weekly

# Check live status across all 20 notebooks
python -m src.src_2.orchestration.kaggle_dispatcher status
```

## 4. GitHub Actions Weekly Automation

The workflow file is deployed at [weekly_pipeline.yml](file:///.github/workflows/weekly_pipeline.yml).
- Automatically triggers every **Sunday at 00:00 UTC** (after Friday closes and weekend settlements).
- Can also be triggered manually via `workflow_dispatch` with a choice of `weekly` or `initial` mode.
- Incremental map updates run automatically.
- Dispatches all 20 Kaggle notebook workers.
